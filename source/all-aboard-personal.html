6. Test procedure — scanner and clipboard checks

First tap Check scanner capabilities. Copy text from a fictional certificate using Gallery or Google Lens, then tap Import copied text from clipboard. If browser permission blocks that, long-press the text box and Paste; check the automatically suggested fields. Then choose a fictional certificate photo containing a QR code and tap Read QR code from photo. Check whether a result appears. The app does not follow links or verify credentials. Check the expiry status shown beside each saved record. Select a fictional certificate file, review its details, enter its certificate number if present, and save. Edit the certificate number, delete the entry and use Undo last change. Tap Download wallet backup and keep the JSON file in Downloads. Close and reopen this HTML page. Tap Reload wallet and show result. If the entry disappeared, choose the JSON backup using the Restore control above. That tests recovery even if your browser discards local storage.

No-expiry records are allowed. Photo selection automatically tries available on-device text and QR detectors; unsupported browsers still need Gallery or Lens text copying. QR results are reviewed automatically after scanning or pasting, and text-file imports use the same field suggestions as pasted text. Review existing duplicates highlights conflicting fields and can export a plain-text report. The report is not encrypted and is for fictional data only. Duplicate review performs a read-only audit and never removes certificates. Duplicate IDs are compared without case, spaces or punctuation; saving a duplicate is blocked. Unnumbered records are checked by certificate name, provider, and completion date when available. Different dated renewals are allowed. If one record has no ID, matching name, provider, and completion date also blocks duplicate saving. Built-in safety and complete-journey simulation buttons test matching, editing, backup validation and expiry logic without modifying wallet data. Backup restoration uses the same duplicate rules as normal saving and is blocked if the backup contains duplicate certificates; no data is silently discarded. The downloaded JSON is unencrypted and intended for fictional data only. All Aboard is a working brand pending trademark clearance. Existing OnboardFlow backups remain compatible. Restoring first previews the backup count and checks duplicate records; replacing the wallet requires separate confirmation. A failed save keeps the prior in-memory wallet. Version 2 and Version 3 backups are supported; certificate numbers are optional in older records. File selection is not a full phone search. QR scanning is available only where the browser exposes BarcodeDetector; PDF decoding and broad photo OCR are not implemented; built-in photo recognition works only on browsers exposing TextDetector. Files are not included in backups; the original may need to be selected again.
